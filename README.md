# Coffee Chat Eval

`@openboa-ai/coffee-chat-eval` executes declared candidates and publishes
provenance-safe evaluation receipts. It owns orchestration, adapters,
isolation, evidence, native metrics, and reports—not Coffee Chat product
behavior, benchmark source bytes, rubrics, or private product state.

## v1 tracks

- `coffee-chat-taste`: 32 families × three conditions = 96 submissions and
  672 sealed Judge calls. It remains `provisional_internal`; the Bench is
  `not_active`.
- `beam-record-core`: six long-memory categories, 20 pinned 100K
  conversations, and 240 upstream-order queries. Category metrics stay
  independent and reproduce the upstream integer-truncation diagnostic.
- `ifeval`: all 541 official prompts with strict/loose prompt-level and
  instruction-level accuracy. Historical GPT-4 responses are excluded.
- `agentdojo-security`: workspace, travel, banking, and slack at native
  `v1.2.2`, with 1,081 episodes. Benign utility, utility under attack,
  targeted ASR, and injection-task solvability are reported separately.

τ²-bench and Terminal-Bench are not v1 tracks. There is no aggregate score,
leaderboard, security certification, or downstream product-performance claim.

The runner profiles are `fixture` (offline fake/replay), `smoke` (minimal live
execution used to prove the native evaluator path), `pilot` (formal retained
sample), and `score` (complete census). The pre-merge portfolio smoke uses only
the following fixed samples: Taste first family with native conditions
`unconditioned`/`target_a`/`target_b` (3 candidate submissions and 21 Judge
calls), BEAM `100K/1` first question in each of six categories (6 queries and
11 Judge calls), nine pinned IFEval prompts (one per checker family), and
AgentDojo workspace `user_task_0`, `injection_task_0`, plus their attacked pair
(3 episodes). Smoke remains calibration evidence and never becomes a score or
security certification.

## Coffee Chat Product connectivity smoke

The admitted `coffee_chat_product` candidate pins this exact public Product
package:

- repository: `https://github.com/openboa-ai/coffee-chat`;
- commit: `e1ac82de77ab12b9b2499771a194ef3db356b3a6`;
- Product CalVer: `2026.8.23`; and
- deterministic package digest:
  `sha256:e39384e00af5d8d5a71aedcde0d960bd4c6797ed227eab9f08d3134b4d712d41`.

This Product CalVer is candidate provenance; Eval retains its own `2026.8.12`
artifact CalVer. `eval-skills-reference-host-v1` verifies the pinned Git origin
and HEAD, clean public package surface, package and manifest identity, and the
declared capability/Skill entrypoints. It discovers and validates those Product
Skills but never executes them. All benchmark-visible turns are generated by
the Eval-owned reference agent stack.

Accordingly every Product receipt says `candidateMode: connectivity_only`,
`capabilitiesUsed: []`, and `productBehaviorExercised: false`. Only sampled
`smoke` is admitted as live connectivity execution; offline fixture/replay is
plumbing evidence, while Product `pilot` and `score` remain `not_implemented`.
This proves no Product behavior or performance. Taste remains public
`not_active`, with numeric Taste results withheld from public reports.

## Rights and retention

The pinned source manifests in [`src/source-manifests.ts`](src/source-manifests.ts)
record the exact commits/releases, license digests, allowlists, exclusions,
notices, retention, and public-artifact policy. Source verification is
fail-closed. “Evaluation only” does not remove commercial-use or attribution
obligations, so raw upstream bytes are materialized only in `EVAL_CACHE_ROOT`
when the manifest permits it. `EVIDENCE_ROOT` is private, content-addressed,
append-only storage. Public reports contain hashes, provenance, denominators,
and native metric names—not task text, candidate prose, Judge responses,
attack payloads, tool traces, synthetic personal data, or secrets.

The Google IFEval source is Apache-2.0, but its fixed native smoke path also
uses NLTK `punkt_tab`. At the pinned NLTK data revision, that package has no
declared license and NLTK classifies its licensing as unclarified. Native
non-fixture IFEval therefore defaults to `rights_hold/rights`. A workspace owner
may supply an exact, digest-bound `ifeval-rights-risk-acceptance-v1` receipt only
for the pinned `coffee_chat_product` nine-prompt smoke. It binds the exact
candidate digest, IFEval commit, and NLTK repository/revision/path/digest, keeps
`licenseCleared=false`, requires an operator-generated private 256-bit nonce,
and permits private internal calibration only—not a
license grant, redistribution, pilot/score, public numeric result, Product
performance claim, benchmark activation, or official measurement gate. Public
provenance exposes only the receipt digest, false clearance, and private-smoke
scope. The nonce makes that digest a hiding commitment; the body, nonce,
operator, timestamp, path, and numeric IFEval measurements stay private. This
private run may prove sampled-runner execution readiness for the
implementation PR while the benchmark lifecycle remains `rights_hold`. Missing
or drifted acceptance or runtime data fails before candidate calls. This is an
engineering control, not legal advice.

## CLI

```sh
source verify --track <track-id>
source materialize --track <track-id> --cache-root <absolute-path> --source-root <pinned-checkout> [--data-root <pinned-data>] [--runtime-lock <absolute-lock>]
plan --track <track-id> --profile fixture|smoke|pilot|score --candidate-config <json-or-absolute-file> [--provider-terms-receipt <absolute-json>] [--isolation-receipt <absolute-json>] [--ifeval-rights-risk-acceptance-receipt <absolute-private-json>]
run --plan <run-spec-or-plan.json> --evidence-root <absolute-path> [--runtime-config <absolute-private-json>] [--ifeval-rights-risk-acceptance-receipt <absolute-private-json>]
portfolio smoke --config <absolute-private-json>
report --run <run-id-or-receipt-path> --visibility internal|public
```

Set `EVAL_CACHE_ROOT` and `EVIDENCE_ROOT` to absolute operator-owned paths, or
pass them to `plan`/`run`. The plan and fixture paths are deterministic and
offline. Candidate and Judge provider credentials belong only to a host-held
broker; the AgentDojo bridge uses its native tool loop with a scoped broker
capability. For a non-fixture provider run, pass
`--provider-terms-receipt <absolute-json>`; otherwise the run is explicitly
`rights_hold`. Pass inspectable isolation separately with
`--isolation-receipt <absolute-json>` when creating the plan. Candidate identity
contains no endpoint, capability token, provider key, isolation bytes, or local
Product path.

An accepted IFEval Product smoke supplies the same private risk-acceptance file
to `plan` and `run`; only its digest enters immutable identity and public
provenance. The normalized body is retained only as private content-addressed
evidence and is never candidate-visible or copied to public artifacts.

For a materialized source, keep the checkout below
`EVAL_CACHE_ROOT/<track-id>/source` (and data below `data` when the manifest
declares a data layer) and write the exact file digest census to
`source-receipt.json`. `source verify --track <track-id> --cache-root
<absolute-path>` verifies that receipt before execution.

Materialization never downloads. The operator fetches and verifies the exact
upstream revision first, then supplies the checkout with `--source-root` (and
BEAM's parquet checkout with `--data-root`). IFEval defaults to the committed
Eval-owned lock at `runtime-locks/ifeval-requirements.txt`; BEAM's six
LLM-only scorers use the committed Eval-owned lock at
`runtime-locks/beam-eval-requirements.txt` (including the parquet reader), and
other tracks bind an upstream `uv.lock` or pinned `requirements.txt` when
present. BEAM's selected scorers never tokenize, so its bridge suppresses only
the upstream import-time Punkt download calls and restricts NLTK to the empty
evaluator-owned data path; it rejects rather than materializes Punkt data. After
materialization, create `<cache>/<track-id>/runtime` with the pinned `uv` lock
in offline mode. `run` invokes that runtime directly and never downloads or
mutates the source checkout; a missing runtime is unavailable host evidence,
not an automatic installation opportunity.

For a host-held provider smoke, the private portfolio config points to
already-issued local capability bundles. The provider key itself is never
accepted in JSON, never passed to a candidate/Judge, and never written to
evidence. An operator that wants the portfolio command to create separate
per-track proxies provides a private `broker` object with the absolute ignored
`providerEnvFile`, its `providerKeyEnv` name, and optional
`upstreamUrl`/`ttlSeconds`. A dedicated proxy child process loads that file; the
Eval/evaluator parent rejects the key in its own environment and receives only
scoped endpoint/capability metadata. Every child proxy is closed after the
sequential run.

A Product `run` also receives this private runtime member; its absolute path is
verified against the immutable public identity and never enters a public
receipt:

```json
{
  "productHost": {
    "schema": "product-host-runtime-v1",
    "host": "eval-skills-reference-host-v1",
    "packageRoot": "/absolute/path/to/exact/coffee-chat-checkout"
  }
}
```

For `portfolio smoke`, place that same absolute checkout at top-level
`productPackageRoot`. A privately risk-accepted Product IFEval smoke also places
the exact absolute `ifevalRightsRiskAcceptanceReceipt` at top level. Each track
either points to a private runtime bundle with the matching `productHost`, or
the portfolio-owned broker creates it. Runtime endpoints, scoped capability
tokens, expiries, request caps, and the acceptance receipt body and path remain
private; only their safe digests and execution evidence reach receipts.
Connectivity-only Product receipts withhold native-evidence and TrackReport
digests because their small metric spaces are enumerable; they retain an
execution-receipt digest and explicitly set `privateResultDigestsWithheld=true`.
